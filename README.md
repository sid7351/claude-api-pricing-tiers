# Claude API 价格：Opus、Sonnet、Haiku 每百万 token 报价怎么算，国内开发者真正会卡在哪一步

先解决第一类。

## 官方 Claude API 现在按什么价计费

Anthropic 的计费单位是 token，输入和输出分开算，公开报价都以「每百万 token」为单位。官方文档里当前列出的主力型号大致是这样：

| 模型 | 上下文窗口 | 最大输出 | 输入（美元/百万 token） | 输出（美元/百万 token） |
| --- | --- | --- | --- | --- |
| Claude Fable 5.1 | 1M | 128K | $10 | $50 |
| Claude Opus 5.5 | 1M | 128K | $4 | $20 |
| Claude Sonnet 5.5 | 1M | 128K | $2 | $10 |
| Claude Haiku 4.5 | 200K | 64K | $1 | $5 |

四个型号的输入输出比都是 1:5，输出贵五倍。这一点很关键：如果你的应用输出很长，账单会明显比按输入估算的结果高。

另外，上一代型号在第三方价格汇总里还经常出现。Opus 5 报的是 $5/$25，Sonnet 5 报的是 $2/$10 —— 后者属于上线促销价，Google Cloud 的模型页写明促销期到 2026 年 8 月 31 日，之后回到 $3/$15 的标准价。查价时看到同一代型号数字对不上，多半是踩到了这个时间差。

## 单价之外，还有四件事会改账单

只看单价去估算成本，通常会低估。真正影响结果的还有这些：

**输出长度。** 同一句话，模型的输出 token 数往往比输入多得多，而输出贵五倍。做长文本生成、写代码这类任务，输出才是大头。

**提示缓存。** 缓存读取按基础输入价的 0.1 倍计费，写入则是 1.25 倍（5 分钟有效期）或 2 倍（1 小时有效期）。系统提示、知识库这类反复使用的内容，缓存命中率上去以后输入成本能降一个数量级。

**Batch API。** 输入输出各打五折，代价是拿到结果的时间变长。离线任务、批量清洗、跑评测这类场景基本没有理由不用。

**联网搜索。** 官方网页搜索按每 1,000 次 $10 计费，搜索结果本身产生的 token 还要按标准价另算。

把这些拼起来算一遍，差距比想象中大。假设每次请求输入 4,000 token、输出 800 token，一个月跑 10,000 次，也就是输入 40M、输出 8M：

- Haiku 4.5：40 × $1 + 8 × $5 = **$80**
- Sonnet 5.5：40 × $2 + 8 × $10 = **$160**
- Opus 5.5：40 × $4 + 8 × $20 = **$320**
- Fable 5.1：40 × $10 + 8 × $50 = **$800**

全走 Batch 的话，这四档分别降到约 $40、$80、$160、$400。再假设 Sonnet 5.5 的 40M 输入里有 32M 命中缓存：32 × $0.2 = $6.4，剩下 8M × $2 = $16，输入压到约 $22.4，加上输出 $80，总共约 $102。注意首次写入缓存按 1.25 倍算，这部分省不掉。

所以「Claude API 贵不贵」这个问题，答案取决于你选哪个型号、输出有多长、能不能缓存、跑不跑批处理。同一个应用在这几个开关之间来回拨，月账单差出五到十倍很正常。

## 国内开发者卡住的地方，其实不在单价

官方价格表是透明的，查得到、算得清。麻烦出在下一环。

Anthropic 的服务地区列表里没有中国大陆。这不是「能不能访问网页」的问题，而是注册、验证、付款整条链路都要求海外条件：海外手机号接码、海外信用卡、账单地址、以及和账单地区对得上的网络环境。很多人卡在最后一步——手里有 Visa 或者 Mastercard，但是在订阅页面反复被拒，原因未必是余额，而更像发卡地区、账单地址和网络环境叠加触发的风控。
